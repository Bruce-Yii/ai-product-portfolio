## 1. 用户明确确认的七个优化方向

用户明确表示认可此前七个方向和优先级，后续执行不得偏离：

### P0
1. **职业定位与差异化**：基于真实招聘市场与个人证据，找到有竞争力的 AI 产品经理定位。
2. **案例叙事与产品化表达**：短而有力、产品语言、价值导向；允许合理润色和包装，不能把真实产品工作写小。
3. **信息架构与连续阅读路径**：从打开网站到结束形成连贯、清晰的默认主线，避免多个平级入口、选择疲劳和导航迷路。

### P1
4. **视觉表达与信息可视化**：专业、高级、有质感，同时承担信息传递任务。
5. **证据与可信度**：轻量链接到 PR、Issue、Review、仓库、团队官网和项目官网；不堆砌证据墙。
6. **交互与用户体验**：路径、跳转、返回、案例衔接、图片浏览和移动端体验清楚自然。

### P2
7. **工程质量与长期维护**：性能、可访问性、稳定性、部署、版本和回滚作为交付底线。

## 2. 用户明确认可的六项基础能力

用户明确表示非常认同此前招聘研究提炼出的六项能力，要求落实到作品集：

1. 场景洞察：识别真正值得用 AI 解决的问题。
2. 产品抽象：将复杂业务转化为产品机制、功能和工作流。
3. Agent 设计：任务、工具、上下文、人机协作和异常处理。
4. 技术判断：模型边界、RAG、成本、延迟、可靠性和方案适用性。
5. 效果评测：Benchmark、Badcase、任务成功率、反馈闭环和质量指标。
6. 端到端推进：产品方案、原型、研发协作、验收和迭代。

这六项是基础竞争力，不是首页标签清单。必须映射到具体案例和证据。

## 3. 用户明确新增的进阶能力要求

用户认可高级社招岗位中出现的能力指标，并要求一并吸收。其原话核心是“求其上者得其中”。

因此作品集采用双层能力标准：

- **基础竞争标准：** 2027 届 / 0–3 年 AI PM 岗位的六项高频能力。
- **进阶能力标尺：** 高级 AI PM / AI Platform PM / Product Owner 岗位所体现的战略、商业、平台、治理和组织能力。

新增六项进阶参考：
1. 产品战略与组合管理；
2. 业务价值与价值实现；
3. 平台化与生态能力；
4. 企业级可靠性与治理；
5. 跨组织领导与交付；
6. 商业化与市场拓展。

这些能力用于提高案例问题深度、产品判断质量和长期竞争力，不得虚构已经取得的高级岗位经历、商业 ROI、团队管理或规模化上线结果。每项证据必须区分已执行、已验证、研究 / 设计、规划中。

## 4. 用户明确新增的优秀作品集 UX 研究要求

用户要求研究优秀作品集的真实呈现方式和用户体验，时间新鲜度允许近一至两年，不必像招聘动态那样严格限定到当月。

研究不只读“作品集设计建议”，还要实际看真实网站：
- 首页第一屏如何表达定位；
- 项目如何排序和精选；
- 项目卡片怎样让人知道为什么值得打开；
- 案例如何组织叙事、证据和本人角色；
- 如何让用户沿连续主线阅读；
- 如何提供快捷跳转又不让人迷路；
- 视觉、真实产品截图、视频、原型、交互和图表如何配合；
- 哪些呈现形式值得吸收，哪些只是炫技。

第一轮研究已记录于 [2026-11-10 优秀作品集与高级 AI PM 能力研究](../portfolio-reviews/2026-11-10-portfolio-benchmark-and-senior-capability-research.md)。

## 5. 用户确认的核心执行原则

1. 所有七个方向都要落实到网站，而不是停留在策略文档。
2. 基础能力与高级能力同时吸收；高级能力是向上标尺，不是虚构资历的理由。
3. 差异化和核心能力不是二选一：基础能力必须具备，差异化决定记忆点。
4. 作品集内容允许合理的产品化润色和求职包装；不能因过度保守而把产品级贡献写成普通技术修复。
5. 案例表达要简洁有力但不能遗漏关键判断、取舍、证据和结果。
6. 阅读路径必须连贯；默认主线清晰，深读快捷入口作为次级路径。
7. 视觉优先使用项目已有真实素材；不足部分先写 AI 生图 Brief，再交独立生图窗口执行。
8. 证据链接应小而自然，支持招聘方核验，不抢主叙事。
9. 不应无目标地改网站；每次改动必须有目标、具体问题、方案理由和验收标准。
10. 主负责人先完成独立审查和阶段验收，再交用户完整审阅。

## 6. 后续执行与协作

当前阶段按既定路线推进：
- Phase 1：招聘市场能力矩阵（基础六项 + 进阶六项）与职业定位；
- Phase 2：个人案例、贡献、个人 / 团队责任和证据审计；
- Phase 3：定位与案例文案冻结；
- Phase 4：阅读旅程与信息架构；
- Phase 5：真实素材清单与 AI 生图任务单；
- Phase 6：网站实施；
- Phase 7：独立验收、冻结和回滚。

可使用多个本地窗口做**相互独立、只读的研究 / 审计任务**。W0 / ChatGPT 总控负责统一目标、范围、口径、依赖、合并结论和最终验收。并行窗口不得同时修改同一网站代码或直接部署；未经明确批准不得公开发布、改根域名或改变 noindex。
