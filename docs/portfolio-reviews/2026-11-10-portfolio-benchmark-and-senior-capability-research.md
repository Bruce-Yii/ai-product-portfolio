# 作品集优秀案例与高级 AI 产品能力研究
**研究日期：** 2026-11-10  
**研究范围：** 2025–2026 年公开 PM / AI PM 作品集、作品集 UX 参考，以及 2026 年高级 AI 产品岗位  
**用途：** 为个人 AI 产品经理作品集确定能力标准、阅读路径和呈现形式；不是照搬模板  
**状态：** 第一轮研究完成，后续可由独立窗口补充现场截图和交互复核

---

## 1. 结论先行

本轮研究确认两条必须同时采用的能力标准：

- **当前岗位竞争标准：** 2027 届 / 0–3 年 AI PM 岗位反复要求场景洞察、产品抽象、Agent 机制设计、技术判断、评测和端到端推进。
- **进阶能力标尺：** 资深 AI PM / AI Platform PM / Product Owner 岗位进一步要求产品战略与组合管理、ROI 和价值实现、平台化复用、企业级治理、跨组织领导、规模化交付和生态决策。

高级岗位能力应当作为作品集的**向上设计标尺**，帮助案例呈现更深的判断、取舍和系统视角；它不是把候选人包装成已经拥有多年商业化、组织管理或大规模交付经验。每个能力必须标注真实证据成熟度：已执行、已验证、研究 / 设计、规划中。

作品集 UX 研究得出的方向：

1. 首页先讲清定位和最重要的价值信号，避免多个平级入口。
2. 项目精选而非堆数量；案例标题讲问题或结果，不只写项目名。
3. 案例优先呈现本人角色、关键判断、取舍和证据。
4. 真实产品或可交互原型比纯概念描述更有说服力。
5. 允许用户沿一条主线阅读，同时为深读者提供可回退的快捷入口。
6. 视觉形式应匹配候选人的职业身份与案例内容，不为炫技牺牲可读性。

### 2.2 提炼出的高级能力层

在原有六项基础能力之上，增加六项进阶能力参考：

1. **产品战略与组合管理：** 产品愿景、路线图、多季度目标、资源配置、优先级和 Build / Buy / Retire。
2. **业务价值与价值实现：** 业务案例、ROI、用户采纳、商业模式、收入 / 成本 / 效率指标，以及 Scale / Stop 决策。
3. **平台化与生态能力：** 把跨场景共性需求抽象为可复用平台能力、工具、API、开发者体验和生态接口。
4. **企业级可靠性与治理：** 质量标准、评测、安全、隐私、合规、权限、成本、风险和持续监控。
5. **跨组织领导与交付：** 与 FDE、研发、架构、数据、安全、业务和外部供应商协同，减少交接损耗，推动从 PoC 到规模化运营。
6. **商业化与市场拓展：** 用户 / 市场定位、GTM、定价、客户采纳、商业结果与产品生命周期。

### 2.3 如何纳入作品集

不是把高级能力变成首页标签墙。应把它们转成案例里的更高阶问题：

- 为什么这个问题值得投入？机会成本是什么？
- 为什么选这个产品边界和路线图？什么被明确排除？
- 哪些能力应该自研，哪些应该复用 / 采购 / 接入生态？
- 如何从单一场景抽象为可复用机制？
- 如何定义质量、风险和人机责任边界？
- PoC 通过什么证据决定继续、停止或扩大？
- 如何让业务、工程和其他角色在同一套目标下协作？

每个问题只在有真实证据时呈现。缺少业务 ROI 时，可以展示价值假设、指标设计或验证计划，但不能写成已经产生的业务收益。

### 3.3 从样本中提炼出的 PM 呈现模式

1. **Outcome-first：** 首屏先告诉读者产生了什么变化；没有真实量化结果时，使用可核验的交付物 / 阶段结果，不编数字。
2. **Problem-led titles：** 案例标题写用户问题、业务变化或关键产品机制，而不是只写项目名和技术栈。
3. **Judgment visible：** 明确本人做出的决定、反对过的方案、为什么取舍，以及什么没有奏效。
4. **Role and accountability：** 每个案例明确本人角色、团队组成、负责边界和可归因成果。
5. **Working proof：** 通过可运行产品、原型、仓库、真实截图、测试或评测证明构建能力。
6. **Writing as evidence：** 文章和技术 / 产品分析可作为长期判断力证据，但不能挤占主项目阅读路径。
7. **A clear next action：** 明确招聘方可以联系谁、下载什么、进入哪个最值得看的案例。

### 3.4 PM 案例结构参考

AllthingsPM 的 2026 案例研究模板建议按招聘者阅读顺序组织：Headline result → Context & role → Problem → Evidence → Options / decision / trade-offs → Outcome → Learning。

来源：[PM Portfolio Case Study: A Template From Real Examples](https://www.allthingspm.app/blog/pm-portfolio-case-study)（2026-09-28 发布，2026-11-07 更新）。

本项目吸收其顺序，但保留三个阅读深度：
- 10 秒：案例价值、本人角色和阶段；
- 约 1 分钟：问题、洞察、关键决策、方案和结果；
- 3–5 分钟：证据、备选方案、产品机制、执行、验证、失败和反思。

### 4.1 对本网站的具体 UX 结论

**主阅读路径：**
职业定位 → 精选代表性实践 → 旗舰案例深读 → 支撑贡献 / 外部证据 → 个人总结与联系。

**允许的次级路径：**
- 简历 / GitHub 快捷入口；
- 案例内锚点；
- 上一案例 / 下一案例；
- 对团队作品的官网 / 团队站外链；
- 必要时的“其他项目 / 开源贡献”次级索引。

**不建议：**
- 首页多个平级入口或一开始就让招聘方选择筛选维度；
- 项目卡片只展示名称、技术标签和一张装饰图；
- 每个案例都复制同一种长文模板；
- 复杂动效、桌面模拟器、小游戏式导航等与个人定位无关的炫技；
- 为了追求“单页”而把所有内容塞成长滚动页面，或为了“模块化”拆成迷路的多层页面。

### 4.2 可落地的案例页面模式

- 顶部：问题 / 结果型标题 + 一句话价值 + 本人角色 + 项目阶段。
- 第一屏：一张真实产品界面 / 关键成果图，立即建立项目上下文。
- 正文：按问题、证据、决策、方案、验证顺序讲述。
- 侧边 / 同屏辅助：短导航或阶段提示，不抢正文。
- 关键位置：放小型原始证据链接（PR / Issue / Repo / 官网）。
- 末尾：结果、限制、下一步，以及明确的上一案例 / 下一案例 / 返回作品集。

## 5. 对本人的能力模型：两层标准，而非二选一

### 当前岗位竞争力（原有六项，作为基础标准）

1. 场景洞察；
2. 产品抽象；
3. Agent 设计；
4. 技术判断；
5. 效果评测；
6. 端到端推进。

### 进阶能力标尺（新增六项，作为向上标准）

1. 产品战略与组合管理；
2. 业务价值与价值实现；
3. 平台化与生态能力；
4. 企业级可靠性与治理；
5. 跨组织领导与交付；
6. 商业化与市场拓展。

两层标准同时吸收，所有项目案例都应回答：当前证据能证明哪一层能力？证据成熟度是什么？与目标岗位有什么关系？

建议在内部 Case Matrix 中增加以下字段，而不是把 12 个能力标签全部堆到首页：
- **core_capabilities**：六项基础能力；
- **advanced_capabilities**：六项进阶能力；
- **evidence_level**：executed / validated / research-design / planned；
- **personal_ownership**：个人负责与团队协作边界；
- **proof_refs**：可核验链接；
- **interview_defensibility**：面试追问时能否说明事实和取舍。

## 6. 研究限制

- AllthingsPM 是 PM 培训 / 面试服务商，其目录与文章有商业推广目的；样本发现可用，统计与排名需谨慎。
- UXfolio 的招聘研究主要来自 UX / 产品设计招聘者，不直接等于 AI PM 招聘结论。
- Figma 文章中的作品集主要是设计岗位案例，适合借鉴视觉、滚动、案例排版和交互，不等于 PM 最佳信息架构。
- 个人网站自述的指标、角色和成果未经第三方全面审计；本研究分析的是公开呈现方式，不替其背书。
- 不以案例的资历和数据规模作为本人必须达到的数字标准。
- 研究快照日期为 2026-11-10；后续执行前需检查网站是否仍在线、内容是否有变化。

## 7. 下一步如何使用本研究

1. Phase 1：把六项基础能力 + 六项进阶能力映射到真实招聘岗位，形成两层能力矩阵。
